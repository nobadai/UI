# 농산 캣쳐 HTML Prototype

가상 농산물 유통회사 AI 에이전트 시뮬레이션의 화면 프로토타입입니다. 기준 문서는 `프로젝트_정의서_v0.5`이며, §6.1 관리자용 화면과 §6.2 외부용 화면 구성을 그대로 따릅니다.

> **회사명은 아직 미확정입니다** (정의서 §10.3). 화면에 쓰이는 이름은 `js/core/config.js`의 `BRAND` 상수 한 곳에서만 관리하므로, 확정되면 그 값만 교체하면 됩니다.

저장소 루트의 `index.html`을 브라우저로 열면 됩니다.

## 화면 구성 (정의서 §6)

### 관리자용

| 메뉴                 | 하위 화면                                                              |
| -------------------- | ---------------------------------------------------------------------- |
| 대시보드             | T0 상태 스냅샷, 파이프라인 T0 → T4, 오늘의 매입 판단, 품목 시세        |
| 금일 도매가 예측(ML) | 가격 예측 (소매가 · 중도매가 · 경락가 일괄 표시, D+1 ~ D+18)           |
| 매입                 | 금일 제안 상세 / 제안 이력 / 시장 시세 / 매입 내역 / 매입 설정(상수값) |
| 재무                 | 자산 통합 / 지출 상세 / 보유 자산 현황 / 가용 자산 / 급여 관리         |
| 영업 관리            | 인력 관리 / 배송 현황 / 거래처 현황                                    |
| 재고 · 물류 관리     | 재고 현황 / 출고 이력                                                  |
| 거래처 관리          | 거래 내역 / 영수증 출력 (메일 발송, PDF·XLSX 추출)                     |
| 설정                 | 회원 생성 / 회원 관리(최상위만) / 회사 관리 / 이상치 탐지 알림         |
| 프로토타입           | 외부용 화면 / 시뮬레이션 페르소나 / 오류 화면 미리보기                 |

### 외부용

`외부용 화면`에서 오픈 채팅방, 산지 계약, 재무제표 확인, 사용자 인증, 외부 페이지 관리 항목을 미리 볼 수 있고, `login.html`·`signup.html`이 실제 진입 화면입니다.

## 파이프라인이 화면에 나타나는 방식

`매입 > 금일 제안 상세`가 정의서 §3.1의 하루 한 사이클을 그대로 담습니다.

| 단계 | 화면 영역        | 내용                                                                        |
| ---- | ---------------- | --------------------------------------------------------------------------- |
| T0   | 대시보드         | 가용자금 · 재고 · 확정주문 · 예측을 전원에게 동일 배포                      |
| T1   | 매입 초안        | 시나리오 2~3안. 예산 초과 인지 시 `exceed_reason` 명시                      |
| T2   | 제약 검토        | 3부서 병렬 회신 = 판정 + 데이터 + 이유 + **변경안(`suggested_adjustment`)** |
| T3   | 조정 · 검증      | 부서 변경안 결합, 사전 feedback 루프, Critic 검증                           |
| —    | 사람 승인        | 제한 모드이므로 사람이 최종 선택·승인 (§4)                                  |
| T4   | 재무 · 재고 화면 | 승인 결과가 현금 · 재고 · 손익에 반영                                       |

## 관리 규칙

- 공통 디자인 토큰, 카드, 버튼, 표, 모달, 챗봇은 공통 CSS에서 관리합니다.
- 특정 화면의 배치는 `css/pages/<route>.css`에서 관리하고, `css/pages/app-pages.css`에서 한 번에 불러와 화면 전환 깜빡임을 방지합니다.
- 화면 마크업은 `html` 태그 템플릿을 사용해 HTML 구조대로 자동 포맷합니다. 사용자 입력값은 반드시 `escapeHtml()`을 거쳐야 합니다.
- 반복되는 표·카드·제목 영역은 `dataTable()`, `sectionCard()`, `kpiCards()`, `pageIntro()` 공통 헬퍼로 만듭니다.
- 이벤트는 `bindPage()`에 직접 누적하지 않고 `bindProposalPage`, `bindOperationsPages`처럼 기능별 바인더로 분리합니다.
- HTML 문자열 안의 인라인 `onclick`은 사용하지 않고 JavaScript에서 `addEventListener`로 연결합니다.
- 백엔드 연결 시 `window.AgriSimData`를 API 응답 상태로 교체합니다.
- 마스코트는 `assets/manifest.csv`의 개별 PNG만 용도별로 연결합니다.
- 챗봇은 앱 레이아웃과 독립된 고정 오버레이이며 최초 접속 시 닫혀 있습니다.
- 인증은 Mock 동작이며 실제 토큰이나 비밀번호를 저장하지 않습니다.
- 내부 화면은 공통 Sidebar·Header·Chatbot 셸을 중복하지 않도록 `index.html` 하나에서 렌더링합니다.

## 정의서 반영 기준

- **가격 숫자는 LLM이 만들지 않습니다.** `js/data/mock-data.js`의 시계열은 고정 시드 의사난수로 만든 ML 파이프라인 산출물 대역이며, 새로고침해도 같은 값이 재현됩니다.
- **숫자를 포함한 주장에는 `ref_id`가 붙습니다.** 스냅샷 카드, 제약 회신, 산출 근거 표에 모두 표기하고, 없으면 Critic FAIL이라는 규칙을 화면에도 적었습니다.
- **모든 조회는 `as_of` 시점으로 자릅니다.** 화면 상단과 근거 카드에 기준 시점을 항상 표시합니다.
- **부서는 자기 축의 변경안만 냅니다** (§3.4.2). `js/core/config.js`의 `AXIS_POLICY`가 `logistics=수량·타이밍`, `sales=판매단가·수량`, `finance=금액`을 코드 레벨에서 강제하고, `checkAxisPolicy()` 결과를 제안 상세 화면에 PASS/FAIL로 표시합니다.
- **최종 결합 수량은 오케스트레이터만 산출합니다.** 부서 카드에는 상한만, 결합 결과는 T3 카드에만 나타납니다.
- **완화 지시는 부서 변경안을 그대로 전달합니다** (§3.2). 사전 feedback 루프 카드에 전달 문구와 원본 출처를 함께 보여줍니다.
- 루프 예산은 사전 2회 · 사후 2회이며, 모두 소진되면 `매입 보류`로 안전 종료합니다.
- 고정지출 항목은 §7 시뮬레이션 페르소나에서 산정합니다. 정의가 끝나지 않은 페르소나는 `프로토타입 > 시뮬레이션 페르소나`에서 확인할 수 있습니다.

## 주요 동작 확인

- 대시보드의 시세 카드나 헤더 품목 선택을 바꾸면 그래프와 예측이 해당 품목 기준으로 갱신됩니다.
- 가격 예측 화면에서 소매가·중도매가·경락가 칩을 켜고 끌 수 있고, 예측 지평 슬라이더나 점선 위 지점을 눌러 D+1 ~ D+18 시점을 고를 수 있습니다.
- 금일 제안 상세에서 시나리오를 선택하고, 세 부서 회신의 축 검사 결과를 확인한 뒤 승인 · 재조정 요청 · 매입 보류를 선택할 수 있습니다.
- 매입 설정, 회사 관리, 이상치 탐지 알림에서 바꾼 값은 `localStorage`에 저장되어 새로고침 후에도 유지됩니다.
- 거래처 관리 > 영수증 출력에서 메일 발송과 PDF·XLSX 추출 동선을 확인할 수 있습니다.
- 사이드바 `프로토타입 > 오류 화면 미리보기`에서 400·401·403·404·500·503·오프라인 화면을 직접 열 수 있습니다.

## 코드 포매팅

프로젝트 루트에서 아래 명령을 실행하면 HTML, CSS, JavaScript를 동일한 규칙으로 정렬할 수 있습니다.

```bash
npx --yes prettier@3.6.2 --write "*.html" "css/**/*.css" "js/**/*.js" "README.md"
```

포매팅 규칙은 `.prettierrc.json`, 제외 경로는 `.prettierignore`에서 관리합니다.

## GitHub Pages

`main` 브랜치에 변경 사항을 push하면 GitHub Actions가 저장소 루트의 정적 파일을 GitHub Pages에 배포하도록 구성되어 있습니다. 저장소 Settings → Pages의 Source는 `GitHub Actions`로 선택해야 합니다.
